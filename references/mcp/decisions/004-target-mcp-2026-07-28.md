## Context

MCP evolves by dated revisions. The 2026-07-28 revision requires a
deterministic `tools/list` order, delivers `listChanged` through
`subscriptions/listen`, supports `outputSchema` and `structuredContent`,
treats tool annotations as untrusted, and moved tasks into an extension.

## Decision

- **The package targets the 2026-07-28 revision** and declares it at
  initialization. Older revisions are not negotiated in the first version.
- **Deterministic order** comes from the toolset (ADR-MC-001).
- **List changes** are pushed through `subscriptions/listen`, one notification
  per toolset publication whose fingerprint changed, sent after publication,
  coalesced for slow sessions, never regressing (BEH-MC-009–011).
- **Results** use `structuredContent` with the projected `outputSchema`
  (BEH-MC-005).
- **Tasks** (the extension) are mapped by `@bridger/agent`'s bridge
  ([tasks](../../agent/behaviors/02-tasks.md)) from its `TaskSnapshot` for
  agent runs and from the command companion's `CommandTaskSnapshot` for long
  commands (BEH-AG-015). A deferred direct `tools/call` is always an
  `isError` result carrying the draft id: nothing stands behind it that
  would complete a task (BEH-MC-005).

## Alternatives considered

- **Support every revision.** Rejected for the first version: each revision
  changes list-change delivery and result shapes; one target keeps the
  acceptance checks finite.
- **Define task states in this package.** Rejected: the task state model is
  the agent package's; MCP is one bridge among several.

## Consequences

**Positive**:

- One protocol revision to test against.

**Negative**:

- Clients on older revisions cannot connect until a later version adds
  negotiation.

**Trade-off accepted**: one revision, done precisely, before breadth.
