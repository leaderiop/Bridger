## Context

Bridger's errors cross several boundaries. Callers narrow them with `Effect.catchTag`. Adapters render them. An audit record carries `error: { _tag, message }`, and a sink may persist it and re-read it in another process. An error that crosses those boundaries must be encodable, and it must not carry anything that should not leave the core: configuration values (which may be secrets), `Context` keys, fibers or raw `Cause`s.

A second distinction matters as much as the encoding: which outcomes are errors at all. A plugin whose build fails has not made `install` fail; it is a plugin in state `failed`. Mixing the two would make `install` non-total and would lose failures that happen later, with no caller.

## Decision

Every named error is a `Schema.TaggedError` (the v4 constructor name, as SPEC.md writes it, is in the API smoke test of [ADR-BR-001](../decisions/001-effect-v4-as-effect-system.md)). Errors carry identifiers and messages only. The table lists every error core defines: the rows from `IncompatibleContract` on were added by later decisions, and the rows whose "Raised by" begins "dies" are defects, never members of an error union. The [overview](../overview.md#errors) lists the same errors by group, and the full union of each host member is in its behaviour file:

- `InstallError = DuplicatePlugin | DuplicateProvider | DependencyCycle | InvalidDefinition | UnknownRealm | IncompatibleContract | IncompatibleEngine` ([03 — Installation](../behaviors/03-installation.md), BEH-BR-018). The full unions of every host member are those of [02 — Host construction](../behaviors/02-host-construction.md), BEH-BR-013, their single source (CCR-BR-032).
- Every mutating operation's error union additionally includes `Unattributed | ReasonRequired | AuditUnavailable | OperationRejected`, with two exceptions. `shutdown` adds only `Unattributed | ReasonRequired`: it skips the latch, is not gated, and proceeds when its `requested` record cannot be written; its only other error is `WouldDeadlock` (BEH-BR-105). `reconcile` fails only with `Unattributed | ReasonRequired | AuditUnavailable | HostClosed`, and `PlanStale`, `ApplyRolledBack` and `PartialApply` from its plan and atomic options ([32 — Generic gate and plan](../behaviors/32-generic-gate-and-plan.md)); gate refusals are per entry and are reported in `ReconcileReport.rejected`, not as the call's error ([ADR-BR-023](../decisions/023-desired-state-reconcile.md)). `AuditWriteFailed` never reaches an operation's caller; the host maps it to `AuditUnavailable` or to the audit-degraded latch.
- **`ConfigFingerprintUnavailable` is a call error; `ConfigFingerprintFailed` is the port's.** The unions of `install` and `reconfigure` also include `ConfigFingerprintUnavailable`; it is raised only when a `ConfigFingerprinter` is wired and the call supplies a new override value. `reconcile` reports it per entry in `ReconcileReport.rejected`, not as the call's error. `ConfigFingerprintFailed` never reaches an operation's caller; the host maps it, like a defect, a timeout, a selection outside the changed paths or a malformed answer, to `ConfigFingerprintUnavailable`, and the call changes nothing and writes no record ([ADR-BR-039](../decisions/039-config-fingerprint-port.md)).
- **`DrainTimeout` names where the drain stuck.** `id` is always the plugin (or `Generation` name) whose leases did not drain, or whose running transition step the call was waiting for when its drain limit expired, and `leases` its count of leases still held — 0 when the call was waiting for a running build step; `realm` is that plugin's realm (absent for a `Generation`), and `target`, the record `{ id, realm }` of the plugin the call named, is present only when `id` and `realm` do not name it — a cascade whose drain limit expired while it waited on a dependent ([ADR-BR-038](../decisions/038-cross-plugin-stop-ordering.md)). The `drain-timeout` event carries `pluginId` and `realm` = `id` and `realm` and, as `target`, the record `{ id, realm }` of the plugin the call named. A caller that catches `DrainTimeout` can therefore tell "my plugin is held" from "a dependent of my plugin is held" without a second lookup.
- **Record-only tag `Interrupted`.** A call interrupted after its `requested` record was enqueued and before its intent was recorded ends with a `failed` record whose `error` is `{ _tag: "Interrupted", message: "caller interrupted before its intent was recorded" }` ([22 — Attributable operations](../behaviors/22-attributable-operations.md), BEH-BR-188). `Interrupted` has no fields and the fixed message above. It is not a `Schema.TaggedError` and never a member of any operation's error union, because the interrupted caller receives no error at all; it appears only in `AuditRecord.error`. A consumer's store that validates `error._tag` against this table must accept it as a record-only tag.
- **Record-only handoff loss tags.** `HandoffExportFailed`, `HandoffVersionUnaccepted`, `HandoffUpgradeFailed`, `HandoffDecodeFailed`, `HandoffImportFailed` and `HandoffAbandoned` appear only in the `error` of a `handoff` system record that ends in loss ([34 — State handoff](../behaviors/34-state-handoff.md), BEH-BR-350), each with a core-written message naming the step. Like `Interrupted`, none is a `Schema.TaggedError` or a member of any operation's error union; a consumer's store must accept them as record-only tags.
- **Record-only tag `DigestRefused`.** A start refused by the `RefusalList` outside step 4b writes a `start-refused` system record whose `error` is `{ _tag: "DigestRefused", message: "digest refused: <reason>" }` ([28 — Plugin principal and mandatory policy](../behaviors/28-plugin-principal-and-mandatory-policy.md), BEH-BR-267). Like `Interrupted`, it is not a `Schema.TaggedError` and never a member of any operation's error union.
- **Activation outcomes are state, not errors.** Missing requirements leave a plugin `waiting`; a build or activation failure leaves it `failed`. `KeyMismatch` and `ConfigInvalid` appear as the cause recorded in that failure, and `install` does not fail for them.
- **Consistency fixes to SPEC.md.** `PluginHandle.restart` has the same error union as `Host.restart` (SPEC.md omitted `DrainTimeout | WouldDeadlock`); `awaitIdle` and `inspect` also fail with `HostClosed`.
- **No values.** No field carries a configuration value, a key object, a fiber or a raw cause; full causes stay in the core's diagnostics. A `ConfigInvalid.message` names paths and expected forms and omits the offending values ([ADR-BR-018](../decisions/018-configuration-decoded-before-build.md)). A `ConfigFingerprintUnavailable.message` is written by core and names only why the fingerprints are unavailable (`"selection outside the changed paths"`, `"malformed answer"`, `"timeout"`, the port error's `_tag`, or `"defect"`); it never carries the port's own text, which could quote a value ([ADR-BR-039](../decisions/039-config-fingerprint-port.md)).

## Alternatives considered

- **`Data.TaggedError`.** Rejected: it has no schema, so the audit record and any adapter crossing a process boundary would need a second, hand-kept encoding of every error.
- **Plain `Error` subclasses with numeric codes.** Rejected: no `catchTag` narrowing, and hand-allocated codes collide (the precedent qadi ADR-QD-008 records).
- **One `BridgerError` with a `code` field.** Rejected: unions could not narrow per operation, so callers would handle impossible cases.
- **Carrying the raw `Cause` in errors.** Rejected: causes may embed configuration values or service objects, and they do not encode.

## Consequences

**Positive**:

- Every error is narrowable and encodable, and safe to log or audit as is.
- Each operation's union states exactly what can go wrong.

**Negative**:

- Error unions are wide once the four GxP errors are added to every mutating operation, even on hosts with no sink, gate or attribution requirement.
- Diagnosing a build failure needs `inspect` or logs; the error alone carries only a message.
- `LeaseRevoked` carries `serviceId` *or* `id` (a plugin's or a generation's), so consumers must branch on which field is present.

**Trade-off accepted**: wider unions and thinner errors, in exchange for errors that can cross any boundary without leaking a value.
