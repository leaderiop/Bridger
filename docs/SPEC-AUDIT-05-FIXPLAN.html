02 · Decisions to make first

These need the spec owner's call. Each lists a recommended option and the main alternative. H7, H8 and most mediums have one obvious fix and need no decision.

D1Who owns a child stop that the parent's operator-rooted stop parked, when the sub-scope then closes?

Closes
H1, CL1, CL2, CL3, CL8
Recommended
The parent's stop keeps it. A sub-scope close or unmount only waits, never resumes or revokes. The resume-and-revoke rule (14:95, 08:752, 09:421) applies only to a stop parked outside the parent's stop. If the closing fiber itself holds a lease on the child, the close fails with WouldDeadlock and the child stays parked with the operator call. That is the only case where waiting cannot end.
Alternative
The sub-scope close takes the stop over and revokes, and H1's wait rule is dropped. Simpler, but a finalizer overrides an operator's force: false, which round 4 chose against.

D2What bounds a fence admission: the ambient Scope or the transaction handle?

Closes
H2, B1, B3
Recommended
The handle. fence(tx) already receives tx, and the adapter ends the admission when that transaction commits or rolls back. publish drops Scope.Scope from its requirements, no write helper changes signature, and an inner Effect.scoped can no longer cut the admission short. Adapter property 8 becomes "end each admission at commit or rollback", tested in both suites.
Alternative
Keep the Scope and add Scope.Scope to every write helper in event-store, sequence, keyring, federation and command, plus a rule forbidding an inner Scope. More signature churn, and B1 stays a documentation rule.

D3How does a loop write task state, and how does Tasks.cancel reach it?

Closes
H3, A1, A2, PL3, PL4
Recommended
A separate write port, TaskRegistry.register(task, cancel), scoped to the loop's activation. It returns a writer for that task, and its cancel handle takes (context, { handedDraftId? }). Tasks.cancel looks up the handle, and AgentLoop.cancel delegates to Tasks.cancel. When the registration's scope closes, non-terminal tasks end failed "loop-stopped" under BEH-AG-016. While a subagent's draft is pending on its parent, an unmarked cancel ends it "handed-to-parent", and the first cancel to reach the handle decides. The registry is internal and only spawnSubagent may pass handedDraftId.
Alternative
Put create/publish on Tasks itself. Fewer types, but every reader of Tasks can then write.

D4How does a re-bootstrap retry push the outbox while links are suspended?

Closes
H4, H6, F1, F2, F3, PL8, PL9
Recommended
A new link state, delivery-only, used only in step 1 of a retry. The control endpoint exchanges an offer that lists only the delivery imports (named by import id, not serviceId). Their proxies open, and a delivery import may have no dependent but the outbox relay. RebootstrapMarker gains installAttempted: boolean, set before the first install and cleared only after step 4. At activation, the flag keeps links suspended whatever the step. A step-2 failure resumes links only when the flag is false.
Alternative
Never lower the marker below "installing" once an install began, and drop step 1 from retries (the outbox was already settled before the first install). Smaller, but a retry can then never push new outbox entries written meanwhile.

D5Where does an import proxy get residency labels before any link is dialled?

Closes
H5
Recommended
Require ManifestPeer.residency for any import that carries a residency, and make the proxy transport's profile carry it. Check 37 covers exports by the dialer's profile and imports by the manifest.
Alternative
LinkDialer.profile(peer), which needs no connection. Keeps one source for both directions, but adds a port member every dialer must implement.

D6How does a dev reload skip a declared handoff?

Closes
H9
Recommended
Add cold?: boolean to ReplaceOptions and to ReconcileOptions (applied to every replace the reconcile issues), defined in 34 beside HandoffCallOptions.
Alternative
Kit strips handoff from the reloaded definition. No core change, but it changes the definition and can change its digest, which the refusal list and the loader gate read.

D7How do errors and reports name a plugin?

Closes
C2, CL13, PL15
Recommended
{ id, realm } in structured fields (DrainTimeout, CleanupError, CloseReport, ReconcileReport, providerIds, DuplicateProvider, DependencyCycle.path, TestHost, entitlement counters and NotEntitled). The canonical key JSON.stringify([realm, id]) is used only where a single string is required (context references, record keys). BEH-BR-147 says exactly that.
Alternative
The canonical key everywhere. One rule, but readers have to parse JSON to show a plugin's id.

D8How are audit facts that arise after the close report made visible?

Closes
C3, C4, C5, G4
Recommended
A HostControls.closed: Effect<CloseTail> that resolves after the host scope has closed and the writer's final flush has ended, with { auditDegraded, lastNumbered, lastWritten }. During shutdown the latch is set without publishing a snapshot or event. auditPosition gains lastNumbered. The lost-record log becomes BEH-BR-192's fourth correlationId exception. GxP's recordClose reads closed.
Alternative
Delay the final snapshot and closed until after the flush. Fewer new members, but it moves BEH-BR-109's final revision and lengthens every shutdown by the flush.

D9What may an archive's seal check claim?

Closes
H10, G7
Recommended
Give readArchive receiptVerifiers, pinnedTrustRoots and expected heads taken from the archive's own high-water marks, and pass all three to verifyBundle. The remaps of BEH-GX-140 become named exceptions in INV-GX-009 and BEH-GX-171.
Alternative
State that archived anchors stay unconfirmed and list headMismatch as not checked. Honest and small, but archives then never confirm anything.

D10What protects shred tombstones when a whole-store re-bootstrap replaces a KeyStore that shares the outbox database?

Closes
B6
Recommended
A keyring onStoreSwap participant that reads tombstones, pending steps and acknowledgements before the swap and re-applies them after the OriginChange, before decrypt serves.
Alternative
Forbid a shared KeyStore under whole-store installs. Simple, but it removes the setup the keyring overview documents.
