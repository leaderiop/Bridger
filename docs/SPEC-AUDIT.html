02 · Patterns

Most medium findings trace back to five root causes. Fixing the cause closes several findings at once.

Lazy activation not propagatedThe dormant state is missing from landing rules (03, 07), the completion table (08), the system-stop destinations (23) and the clear-config rule (11).
Amendments not back-portedADRs 008, 014, 017, 023, 029, 030 and 043 still state rules later ADRs changed. Gap G35 is closed, but four places still say the GxP companion is "not present".
Port drift between packagesOutboxSettlement.install, ReceiptStoreShape, ProposedRequest, the subagent StartRequest and MCP's context are each typed differently on the two sides.
Trust boundaries left openEvent origin is not tied to the sending peer; received shred notices skip local checks; tasks are readable by id; the dispatch call log loses the caller.
Risk and URS overstate the designURS-BR-023 is absolute where shutdown and system transitions proceed; RSK-BR-063 scores a control that does not exist; RSK-BR-014 omits the ungated child-mount route.
03 · High severity

H1Correlation ID is banned from host events and logs, yet a partial apply must publish it contradictionverified

Where
core/behaviors/22-attributable-operations.md:320-324, :1009-1017 vs 32-generic-gate-and-plan.md:966-970; 13:334
Evidence
22: the value "MUST NOT appear in snapshots, Host.events, logs, spans or metrics". 32: a PartialApply "MUST be logged at error level naming … the correlationId" and published as reconcile-partial { scope, correlationId, notUndone }. inspect().pending.correlationId also breaks "to nothing else".
Fix
Drop the correlation from the event and log (use the parent requestedRecordId), or list these channels as explicit exceptions in BEH-BR-187 and BEH-BR-192.

H2An approved plan can apply a different version or different config values gapverified

Where
core/behaviors/32-generic-gate-and-plan.md:519-539; INV-BR-043
Evidence
expect compares entries, actions, configChange.paths, policy and expected, but not incoming (version/digest), consentDiff or values. A plan approved for v4.2 passes with v4.3, since both are replace. INV-BR-043 promises "applied exactly as reviewed or not at all".
Fix
Compare each entry's incoming version and digest; compare config fingerprints when a fingerprinter is wired, or say plainly that values are not covered.

H3Calls that land in dormant, or are refused after step 4b, never complete gap

Where
core/behaviors/08-operation-legality.md:282-295 vs 08:435, 27:713-718, 28:957-966
Evidence
The completion table says enable completes when the plugin "has entered starting or waiting", and each operation "MUST complete … exactly at the point given". The same file sends enable to dormant; 28 sends a refused start to disabled.
Fix
Add completion rows for "entered dormant" and "start refused after step 4b → disabled", each with its result and terminal record.

H4GxP seal verification reads receipts through a write-only port contradictionverified

Where
gxp/behaviors/21-sealing-through-audit-chain.md:120,138 vs audit-chain/behaviors/02-anchoring.md:89-91
Evidence
verifySeals takes receipts: ReceiptStoreShape; audit-chain defines that shape with only put. The read port is ReceiptReaderShape (audit-chain 05). confirmAnchors's unconfirmed list maps to no finding kind.
Fix
Take audit-chain's ReceiptReader and add an anchorUnconfirmed finding.

H5Approval binding v2 cannot be built from ProposedRequest contradictionverified

Where
gxp/behaviors/09-approval-tickets.md:311-318 vs 09:97-105, 11-signature-linking.md:133, 20:607; INV-GX-003
Evidence
ProposedRequest has operation, target, actor, reason, definition and configChange only. bindingOf needs onBehalfOf, undo, definition.manifest, allowChildren and mandatoryInterceptions. Calls from plugin code, undos and manifest definitions all fail as binding-mismatch.
Fix
Add the v2 request fields to ProposedRequest and to INV-GX-003's source list.

H6Shared trail sink vs one-host chain sink contradictionverified

Where
gxp/behaviors/03-trail-sink.md:84-86 vs audit-chain/behaviors/01-hash-chain-sink.md:120-123; gxp 22:71
Evidence
GxP: "The layer MUST be safe to share between hosts". Audit-chain: "One HashChainSink instance MUST serve exactly one host … second host … break marker". TrailSinkStatus holds no hostId, so a collision on host A makes the gate refuse on host B.
Fix
Require one sink and one status per host, or key both by hostId.

H7GxP acceptance check 47 needs an IQ row and an evidence-pack file that do not exist gap

Where
gxp/behaviors/22:201-212, 20:615-618 vs 15-installation-checks.md:75-94, 17-evidence-pack.md:51-76
Evidence
No IQ row or sections member covers trailGate or ChainGate. The pack "MUST contain exactly the files of the layout", which has no status file, and buildEvidencePack takes no status input.
Fix
Add an IQ row, an expected member, and a pack input and file for the status counts.

H8A failed incarnation raise after a whole-store install reuses sequence numbers gap

Where
durable-bus/behaviors/06-replay-and-snapshots.md:333-340; 01:231; federation/behaviors/02:399
Evidence
Order is prepare → run → IncarnationSource.raise. Only a failed run is defined. If raise fails or the process crashes after run, the bus resumes on the replaced store under the old origin and issues (origin, stream, sequence) 1… again, the reuse BEH-DB-004 forbids.
Fix
Raise before run, or persist a swap marker that keeps the outbox frozen and blocks start until the new incarnation is recorded.

H9Dispatch call-log entries lose the caller's actor and annotations gap

Where
command/behaviors/02-dispatch.md:186-207, :696 vs core/behaviors/29:700-704, 22:272; mcp 01:176; agent 03:296
Evidence
Core fills a call entry's actor from the calling fiber's CurrentActor; only steps 4 and 7 run inside CallerContext.serve. MCP and agent pass the session actor and taint only in options.context, so entries are logged as unattributed with no taint (breaks BEH-AG-021).
Fix
Run step 8 and the step-5 hooks inside CallerContext.serve(resolved context); add a check comparing logged actor and annotations with options.context.

H10A subagent cannot receive the parent's restricted toolset or taint gapverified

Where
agent/behaviors/04-subagents.md:146-157 vs 01-agent-seams.md:147-155
Evidence
"The subagent MUST use that one restricted toolset … MUST NOT pin a toolset of its own". StartRequest has selector but no toolset, taint or parentTaskId, so the loop pins a fresh, possibly wider toolset and starts untainted (INV-AG-003, INV-AG-005).
Fix
Add a spawn-only start variant carrying the parent's PinnedToolset, taint set and parentTaskId, and forbid pinning when present.

H1113+ error tags are in neither error catalog contradictionverified

Where
kit/behaviors/07-error-catalog.md:50-56 (BEH-KT-049), docs/guides/error-catalog.md
Evidence
The catalog "MUST contain exactly one entry for every … tag a Bridger companion specification defines". Missing: GxpLayerInvalid, GxpCoreVersionUnsupported, TrailWriteFailed, TrailReadFailed, SignatureDeclined, SignatureCaptureFailed, GateAttachFailed, FingerprintProposalFailed, FingerprintKeyUnavailable, FingerprintMalformed, FingerprintCompareRefused, AnchorReadFailed, AnchorWriteFailed, AnchorUnconfirmed.
Fix
Add a GxP section to BEH-KT-052 and the guide, plus AnchorUnconfirmed. Consider a verifier check that compares Schema.TaggedError tags with the catalog.

07 · Method and limits

Eight read-only reviews ran in parallel: core behaviours 01–12, 13–24 and 25–34; the rest of core (ADRs, invariants, URS, risk, validation, process); the GxP companion against core and audit-chain; loader, kit, command, mcp and agent; remote, federation, durable-bus, event-store and sequence; audit-chain, entitlement, keyring and the guides. Each was told to skip what the verifiers check and anything already listed as a known gap in a CCR or roadmap, and to quote both sides at file:line. The coordinator re-read 15 findings in the source; all held.
