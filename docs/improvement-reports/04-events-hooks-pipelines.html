Improvement report 04 · Bridger vs the Cordis lens

Events, hooks, policy gates and pipelines

State (2026-11-22): everything below this paragraph is the original review, kept as written. All findings are resolved as built on spec/events-report-04 (11 commits after report 03; suite 666/666; traceability, event-catalog, companion and report checks 0 failures); see Resolution status for what was built and Not checked for the corrections. The operation gate is BEH-BR-217 to 224, not 313 to 321 as the first reading said.

Bridger has three separate decision and observation mechanisms: the Bridger.Events bus (BEH-BR-137-144), hook points (BEH-BR-297-312) and the operation gate (BEH-BR-217-224, gate.ts; first read as 313-321). Their veto and observe roles are cleanly separated, and Bridger is ahead of Cordis there. The bus itself is thinner than Cordis' catalog discipline. An EventKey carries no dispatch mode, so a mismatch is silent. No generated catalog checks call sites. emit has no back-pressure or ordering statement, and waterfall next is un-memoised with "observer must call next" only a SHOULD.

Recommendations

R1 · EV-01, EV-06

Mode belongs to the event key

Rationale

Cordis gives each event exactly one mode, so a listener cannot be registered for a style the emitter never uses. Bridger split on/around by kind but left mode free in the key, so the bug is silent.

Proposed change

BEH-BR-138: EventKey<Args,Result,E,Mode>, Event.make(...)(id,{mode}). BEH-BR-139: on takes emit/parallel/serial keys, around only waterfall. BEH-BR-141-143: each dispatcher accepts only its mode. Amend ADR-BR-020. No unmoded keys exist.

Cost / risk

Low: 4 dispatchers and one Event.make. Events dispatched by two modes today need splitting.

Verification

// @ts-expect-error tests per mismatched pair; runtime test that a mismatched dispatch dies with the event id.

R2 · EV-02, EV-08, EV-13

Generated, verified event catalog

Rationale

Cordis' @mode tag, generated catalog and verify-cordis-catalog make drift a CI failure. Bridger has the culture (verify-traceability.sh, verify-companions.sh) but not for events.

Proposed change

New references/core/scripts/verify-events.sh (plus per-companion): extract every Event.make, HostEventBody tag and HookPoint.make name; generate appendices/event-catalog.md (id, mode, args, result, owner behaviour); fail if a call site names an id or mode absent from it. PROC rule: a new event needs a catalog row in the same change. Agent loop events join the catalog (EV-13).

Cost / risk

Medium: parser over snippets marked "not type-checked". Start with the prototype source and a regex for Event.make.

Verification

Seed a mismatched fixture; the script must exit non-zero.

R3 · EV-05

Waterfall roles and once-only next

Rationale

Cordis admits "not calling next vetoes" is right for policy and a bug for observers. BEH-BR-143 repeats the trap as prose.

Proposed change

around(event, fn, {role:"observe"|"decide"}) (as built; the role is required). For observe the bus passes next; if the listener returns without calling it, the bus runs the tail and records listener-failed ("observer skipped next"). next is memoised; a second call is a defect. Consequential decisions use a hook point (BEH-BR-308), keeping BEH-BR-144 intact.

Cost / risk

Low-medium: changes the type of waterfall, rare use today.

Verification

Observer that skips next still reaches final; double next defects; decide short-circuits.

R4 · EV-03, EV-04, EV-12

Bounded emit and stated ordering

Rationale

fireAndForget forks without limit; the spec is silent on order, capacity and re-entrancy. For a GxP runtime, "lossy but silent" is the wrong default.

Proposed change

BEH-BR-141: per-listener in-flight bound (default stated), overflow drop plus a new listener-overflow host event; no completion-order guarantee; cross-emit FIFO only for serialised listeners. BEH-BR-144: emit-depth annotation with a cap; exceeding it is a defect naming the event chain.

Cost / risk

Medium: touches begin, fireAndForget and NFR-BR-007 wording.

Verification

Stress test with a blocked listener: bounded fibers plus the overflow event; recursion test hits the cap.

R5 · EV-06, EV-09, EV-10

Align policy surfaces and vocabulary

Rationale

An author must choose between serial, around, a hook point and a gate; the specs say it only in scattered "Settled" paragraphs.

Proposed change

One decision table in the core overview or 16. Glossary rows for FailurePolicy vs OnErrorPolicy vs listener failure. A defaults table for HookPointOptions and an admission rule rejecting onError:"skip" on veto unless allowed.

Cost / risk

Low: documentation plus one admission check.

Verification

Traceability check that every hook option has a default row; test of the admission rule.

R6 · EV-08

Listener failure attribution

Rationale

listener-failed carries a message only; HostEvent.pluginId is optional (events.ts:27).

Proposed change

BEH-BR-141 and HostEventBody: listener-failed MUST carry pluginId (owner) and the listener contribution id.

Cost / risk

Trivial.

Verification

Test that a failing listener's event names its owner.

Not checked / uncertainties

  • Corrected from the first reading: BEH-BR-146 is about key resolution in realms, not a global-listener answer; the gate behaviours are BEH-BR-217 to 224, not 313 to 321; the “no event is used with two modes” remark was wrong for the prototype's tests; EV-13 does not hold as stated (see status).
  • Reproduced on the old code (a throwaway test on the commit before this work, since removed): an on listener registered on a waterfall-dispatched event was never called (EV-01); next run twice ran the tail twice (EV-05); a failing parallel listener interrupted its sibling mid-run (EV-07); a listener re-emitting its own event reached depth 200 with no stop (EV-12). Each fix has a test, and removing the mode check, the once-only guard, the skipped-next repair, the in-flight bound, the depth cap or the drainTimeout pass-through fails one.
  • hooks.ts was read in full against spec 31 (registration, wake, the three phases, breaker, settle, decision record): no contradiction found beyond one redundant ternary, removed. The enrich and advise phases run their contributions concurrently with no bound other than the number registered and the dispatch deadline; that is the specified behaviour (BEH-BR-311) and was left as is. The script checks the defaults table: field names, the literal defaults, and that every required row is a required field of hooks.ts and every other row is optional there.
  • The catalog extractor is regex-based. It follows relative named imports, namespace imports and transitive re-exports; it refuses any Event.make that is not a declaration with a literal id and mode (so a helper-built or computed key fails the gate instead of escaping it), and flags a dispatch through a key the file neither declares nor imports. A dynamic import() of a key module is not followed, but its keys are still literal declarations in their own file.
  • inspect lists each listener's cumulative dropped, kept after the overflow episode ends.
  • Durable-bus and references/mcp were read for what touches Bridger.Events: only forward (BEH-DB-050) does. Its ordering was derived: BEH-DB-033 orders handler calls per (origin, stream), so forward starts its emits in that order, one at a time; emit promises no completion or cross-emit order to core listeners, so the spec now says a listener needing the order registers serialised. The target is an "emit"-mode key. The MCP host tools only read Host.events.
  • Loaded-run stability: the touched test files ran 8 times, and the full suite once, under six busy-loop processes with no failure; no longer sweep.
