Improvement report 06 / lens: Cordis, DeepSeek Harness

Security, access control, sandboxing, GxP/audit and trust

State (2026-11-22): the original review is kept as written below. All 11 findings were checked against the specification and the prototype; 10 were partly wrong in their premise or already specified, and all are resolved in references/* and prototypes/host-core (see Resolution status). The Cordis table shows Bridger now. Not built: a production worker adapter, a production evaluator and a kill-switch loop; the loader pieces are reference kernels.

Bridger is already stricter than Cordis on trust: signed statements, no default policy, a separate first-party statement for in-process code (BEH-LD-065) and explicit "attribution, not isolation" non-claims. The weak point is the gap between declared and reachable authority. Declarations are enforced at compile time and, at run time, only for listen and contribute (BEH-BR-268), with no UNDECLARED/INACTIVE_ACCESS analogue. Partner plugins have no supported tier. Irreversibility is not modelled as a class, so the gate and approval plan cannot order or flag it. Audit integrity is well specified; what remains is tying anchor freshness to irreversible operations and attributing provider-originated mutations.

Not checked / uncertainties

  • S1 was run, not inferred: test/sec-closed-context.test.ts shows the leak before the fix and its removal after; reverting closedContext makes two tests fail.
  • A ticket consumed by a rolled-back forward action is not re-issued: the undo is gated as its own request with undo: true and needs a binding of its own (gxp BEH-GX-093, core BEH-BR-325). test/sec-undo-binding.test.ts runs both cases with a single-use gate; without the undo's binding the apply ends PartialApply.
  • The prototype now has a worker_threads adapter (worker-adapter.ts), a CommonJS evaluator over verified bytes (evaluator.ts) and a kill-switch kernel (kill-switch.ts), each with tests. They are reference implementations: the evaluator does not load ES modules, its timeout bounds synchronous code only, and the adapter is for first-party code and testing. Six probes are not the whole attack surface (BEH-RM-073).
  • ERP-layer authorization (docs/ERP-ACCESS.md) was read in full: tenant and company scope is added by Records and cannot be widened by a policy, and permissions are data. The one gap, a lookalike Records or Identity provider, is closed by the provider allow-list (S11) and is now stated in ERP-ACCESS section 5, with custom predicates named as plugin code. Spike 08 is the health spike, not authorization. Everything is Draft/Planned.
