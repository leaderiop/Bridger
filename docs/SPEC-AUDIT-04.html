03 · High severity

H1A sub-scope close or unmount revokes leases inside a stop rooted in an operator call or in shutdown regressionverified

Where
core/behaviors/14-children-and-groups.md:73-83 (and :422-427) vs 09-leases.md:416-433, invariants.md:632-643 (INV-BR-017)
Evidence
14 (round-3 fix): when the parent's stop is already removing the child, the finalizer's wait "MUST be bounded by BridgerOptions.drainTimeout … at the limit the host MUST revoke the leases still held on the child, as a removal with no caller does". 09: force "MUST NOT be applied unless the caller passed force: true, except where this specification names a path with no caller" (runtime failure, shutdown limit, refused background restart, cascades so rooted), and "A path whose cascade root is an operator call MUST NOT revoke without that call's force: true: on expiry it MUST fail the call with DrainTimeout and park the stop". For shutdown, revocation waits for the overall limit. Neither list names a sub-scope close or unmount, and INV-BR-017 also still omits the refused background restart.
Fix
Make the finalizer's wait follow the limits of the parent's stop (park with the operator call, the overall limit for shutdown) instead of its own drainTimeout. Or name the sub-scope and unmount paths in BEH-BR-086 and INV-BR-017 and say they override force: false.

H2A subagent cannot tell whether its parent took its draft, so it cannot choose between "handed-to-parent" and withdrawing gapverified

Where
agent/behaviors/02-tasks.md:528-531, 04-subagents.md:313-318 vs 04-subagents.md:299-304, 02-tasks.md:169, 01-agent-seams.md:145
Evidence
The subagent whose draft the parent took "MUST end cancelled with … "handed-to-parent", without calling draftWithdrawal.withdraw". A sibling whose draft is not the parent's "MUST end under BEH-AG-016" and calls withdraw. Both are ended the same way, through Tasks.cancel(taskId, parent.context). The signatures carry no marker: cancel: (taskId, context?) and AgentLoop.cancel: (taskId). Only the parent loop knows which draft it took, and the subagent's loop runs in its own ephemeral realm. A wrong guess withdraws the draft the parent waits on, or leaves a draft unreported (INV-AG-008). This is the round-3 H3 fix.
Fix
Give the cancel a hand-off marker (for example Tasks.cancel(taskId, ctx, { handedDraftId })). spawnSubagent passes it only for the subagent the parent took.

H3DurableBus.fence must wait for open transactions to end, but no port lets the bus see a transaction end gapverified

Where
durable-bus/behaviors/06-replay-and-snapshots.md:447-460, 08-testing-and-acceptance.md:115 (check 45) vs 02-transactional-outbox.md:36-38, :153-170, 03:79-100
Evidence
06: "Setting the freeze MUST wait … until every transaction that has passed fence has committed or rolled back". But fence(tx) returns Effect<void, OutboxFrozen> and needs no Scope. StoreTransaction is { readonly handle: unknown }, and neither OutboxStore nor InboxStore has an operation that reports a transaction's end or holds a freeze row. Check 45's wording ("the freeze is set only after every transaction that passed the fence before it has ended") can wait for ever under steady writes, since new transactions keep passing the fence.
Fix
Add an adapter obligation, for example a freeze flag the adapter checks inside transaction that serialises with open writers, or a scoped fence whose finalizer runs at the transaction's end. Reword check 45: the freeze refuses new transactions first, then waits for those already admitted.

H4multiplex now needs the physical end's TransportProfile, but federation's links have none to pass regressionverified

Where
remote/behaviors/07-transports-and-adapters.md:293-295, :313-322 vs federation/behaviors/03-links-and-skew-handshake.md:43, :47, :82-83; 06-kill-path-placement-and-skew.md:300-301
Evidence
Remote (round-3 H8 fix): Transport.multiplex: (physical: Connection, profile: TransportProfile), the same for GuestTransport.multiplex, with profile "the profile of the transport end that made physical". Federation's dial and accept yield bare Connections, links "MUST be split with … Transport.multiplex … GuestTransport.multiplex", and 06 relies on "the transport profile of the link's connection". The word profile appears nowhere else in federation.
Fix
Add profile: TransportProfile to LinkDialer and LinkListener (or to what they yield) and pass it to both multiplex calls in BEH-FD-017.

07 · Method and limits

Eight read-only reviews ran in parallel with the same split as rounds 2 and 3. Each first read the uncommitted round-3 diff for its slice and grepped every other place a changed rule appears, then read the files earlier rounds had skipped. Duplicates (bare plugin IDs, the parked-stop resume lists, BEH-BR-096, INV-BR-016, the unbounded entitled wait) are merged. The coordinator re-read the four highs and seven other findings in the source; all held. A suspected loss of nested transitions in the single-valued CurrentTransition was checked and dropped: a lazy plugin's load runs in its own build step, and wake does not wait (27:556, 27:678).
